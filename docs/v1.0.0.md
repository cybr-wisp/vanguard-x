# Vanguard-X v1.0.0

Initial validated release of Vanguard-X, a real-time multi-sensor tracking and geospatial event-processing system.

## Included in v1.0

- UDP + Protobuf sensor ingestion
- Netty gateway
- atomic per-sensor sequence validation
- Kafka event processing
- EKF and interacting multiple-model estimation
- Mahalanobis gating and multi-target association
- track lifecycle and duplicate suppression
- Redis-backed state
- spatial and geofence processing
- Spring Boot REST/WebSocket API
- React/TypeScript tactical visualization
- Prometheus/Grafana observability
- deterministic simulation and benchmark tooling

## Numerical hardening

The production tracking path avoids explicit covariance-matrix inversion.

Kalman gain, NIS, NEES, Mahalanobis distance, and IMM likelihood calculations use linear-system solves with explicit handling for invalid numerical states.

The EKF covariance update uses Joseph stabilized form.

## Concurrency

Sequence validation uses atomic ConcurrentMap updates so duplicate and gap accounting remains correct under concurrent access.

## Estimator snapshots

Estimator snapshots use virtual state and covariance accessors, preserving combined IMM state and covariance rather than stale inherited EKF state.

## Known limitations

### Local geospatial approximation

The v1.0 demonstration uses fixed local meters-per-degree conversion constants over a bounded synthetic operating region.

This approximation is not intended for wide-area operation. A production wide-area implementation should use WGS84 geodetic coordinates with ECEF/local ENU transformations.

### Kafka representation

Sensor reports arrive through Protobuf, while the current internal Kafka raw-report path uses a text representation. A future release may use a versioned Protobuf-native Kafka contract.

### Duplicate suppression

v1.0 uses calibrated position and velocity thresholds for duplicate-track suppression. Covariance-aware track-to-track gating is planned for future work.

### Architecture

PipelineOrchestrator remains a centralized integration layer in v1.0. Simulation, tracking, spatial processing, and publishing can be decomposed in a later architectural release.
